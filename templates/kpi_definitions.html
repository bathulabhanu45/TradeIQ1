Project Objective

Purpose and business intelligence target.

The primary objective of TradeIQ is to empower e-commerce executives and retail managers with an aggregated, auditable Business Intelligence decision-support platform. Unlike transactional order processing tools that track single customers, TradeIQ focuses on macro financial velocity, category contribution shares, territory penetration, and fulfillment leakage.

Core Deliverables: 7 Animated KPI metrics, 7 Interactive Plotly charts, 7 distinct operational pages, multi-format exports (CSV/PDF).

Problem Statement

Challenges resolved by TradeIQ.

Raw transactional databases (OLTP) contain millions of line-item records with complex returns, promotional vouchers, and status cancellations. Traditional student and prototype systems often suffer from:

  • Order Multi-Counting: Joining orders with line items inflates parent order counts.
  • Improper Returns Handling: Treating refunds as non-existent or deleting orders corrupts fulfillment logs.
  • Division by Zero Crashes: Unhandled zero sales in comparison periods breaks standard code.

7 Key Performance Indicators (KPI) Mathematical Specifications

Standardized formulas implemented across Python analytics and MySQL queries.

KPI Metric Mathematical Formula Database Query Logic Exclusion / Inclusion Policy
1. Gross Sales Σ (quantity × unit_price) SUM(oi.quantity * oi.unit_price) Excludes orders where order_status = 'Cancelled'.
2. Total Discounts Σ (discount) SUM(oi.discount) Only aggregates discounts from eligible non-cancelled transactions.
3. Total Returns Σ (return_amount) SUM(oi.return_amount) Captures full or partial item-level refund amounts on delivered/returned goods.
4. Net Sales Gross Sales − Discounts − Returns SUM(qty*price - disc - returns) Primary operating revenue indicator driving all growth and category shares.
5. Valid Orders Count(Distinct order_id) COUNT(DISTINCT o.order_id) Excludes cancelled orders. Retains returned orders as fulfillment dispatch occurred.
6. Average Order Value Net Sales ÷ Valid Orders (Net Sales / Valid Orders) Guarded against division by zero (evaluates to $0.00 if Valid Orders = 0).
7. Revenue Growth % ((Current − Prev) ÷ Prev) × 100 np.where(prev > 0, ((curr-prev)/prev)*100, None) If prior period has zero sales, returns None and displays N/A.

Second-Year CS Viva Voce Defense Guide

Anticipated technical questions and comprehensive answers for semester examination.

Defense: A cancelled order represents an aborted transaction prior to fulfillment or shipping; no warehouse labor, packing, or delivery occurred. In contrast, a returned order was picked, packed, dispatched, and invoiced. Counting it in Valid Orders accurately tracks logistical throughput and warehouse workload, while the monetary refund is credited back by deducting return_amount in Net Sales.

Defense: When joining a 1-to-many relationship (one order to multiple item rows), joining multiplies parent table rows by the number of item records. If one naively uses COUNT(o.order_id), an order with 3 items is counted 3 times. TradeIQ strictly uses COUNT(DISTINCT o.order_id) in SQL queries and df['order_id'].nunique() in Pandas, guaranteeing 100% mathematical integrity.

Defense: Binary floating-point data types (FLOAT, DOUBLE) store approximate values using binary fractions, leading to rounding inaccuracies (such as $0.10 + $0.20 = $0.30000000000000004). DECIMAL(10,2) is a fixed-point numerical type storing exact decimal digits, making it compliant with GAAP accounting standards and financial audits.

Defense: We never concatenate user strings into raw SQL statements. We use prepared statements with placeholders (%s for MySQL and ? for SQLite). The database engine compiles the SQL query structure separately before binding the parameter values as pure literal values, rendering SQL injection technically impossible.

Defense: Current limitations include the absence of supplier COGS data (preventing net profit calculations) and single-currency reporting in USD. Future enhancements include machine learning revenue forecasting (using ARIMA or Prophet), multi-currency FX conversion, and automated email scheduling with Celery.
